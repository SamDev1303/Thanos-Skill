∞ Six Infinity Stones

Persistent state that survives everything

Six Markdown files in .thanos/ hold all context across sessions, crashes, and context resets. Read them at the start of every loop. Write them after every action.

🟠
SOUL.md
The active goal, stop condition, scope, and assumptions. Written during the Discuss phase. The truth that terminates the loop.
🔴
REALITY.md
Every file in your project read at launch — real code, real structure. The agent never guesses. It reads first.
💜
POWER.md
Test exit codes, build output, lint results, coverage %. Machine proof written after every action. No green = no continue.
🔵
TIME.md
Loop history and Hermes anti-rules. Grows automatically. Every failure writes a lesson. Quality only goes up.
🔷
SPACE.md
Phase queue, task backlog, blockers. Tracks where in the loop we are and what comes next.
🟡
MIND.md
Critic scores 0–100 across six categories. All must reach 95. Visual proof required for UI changes. No exceptions.
↺ The Thanos Loop

One loop is never enough

Humans are always confused the first time. Thanos keeps asking until the real goal is clear, then loops until a cold critic finds nothing wrong.

01

Read All Six Stones

Every loop starts by reading SOUL, REALITY, POWER, TIME, SPACE, MIND. If any is missing, create from template.

↓
02

Discuss — Find the Real Goal

Deep Q&A session. What is the REAL goal (not the surface ask)? What does DONE look like in machine output? Repeats until the human confirms.

↓
03

Plan — Write Criteria First

Acceptance criteria written BEFORE any code. Phase queue written to SPACE.md. Assumptions extracted to SOUL.md.

↓
04

Execute — Sub Agent Builds

One scoped action at a time. Updates REALITY.md and runs the verifier after every change.

↓
05

Verify — Machine Proof

Tests, build, lint, coverage all run. Exit codes written to POWER.md. Any red = back to Execute.

↓
06

Critique — Cold Reviewer

Smallest model. Zero loop history. Scores six categories 0–100. All must reach 95. Visual proof required for UI changes.

↓
07

Learn — Hermes Injects Anti-Rules

Failures become permanent guard-rails. TIME.md accumulates lessons. The main agent reads them before the next execute cycle.

💥 SNAP

All 6 scores ≥ 95 & all verifiers green. It is done. It is inevitable.

🧬 Hermes Protocol

Self-healing. Self-learning.

After every critic failure, Hermes classifies the issue, checks if it's happened before, and permanently injects a guard-rail. The system gets harder to break with every loop.

🔍

H1 — Visual Proof is Mandatory

Critic cannot pass a UI change without a screenshot or DOM snapshot. Text descriptions are rejected.

📝

H2 — Anti-Rule Injection

Every failure writes a permanent lesson to THANOS.md. Format: [ANTI-RULE Loop N]: NEVER {action} because {consequence}

🔁

H3 — Pattern Matching

Before each execute cycle, the main agent reads all accumulated anti-rules and avoids repeat mistakes.

⚠️

H4 — Escalation

Same failure 3+ loops in a row = pause and ask the human. Context rot detected.

🧄

H5 — Fresh Critic Context

The critic NEVER receives previous loop context. This is the Ralph Loop's most important rule.
